# Ручной QA-чеклист — roadmap 7.4

Не выполнено в этой сессии — нет доступа к реальному Android-устройству (см. отчёт по фазам в
[README.md](./README.md)). Нужен минимум один слабый Android 7/8-девайс (или максимально близкий
эмулятор — учитывая, что реальная деградация на слабом железе эмулятором не воспроизводится
полностью, см. план §5.1/§10) + одно современное устройство.

Собрать так же, как для Фазы 0.4: `node scripts/run-android-gradle.mjs assembleSideloadDebug` (после
`npm install` + `npx cap sync android` — все зависимости Фазы 0.3 уже в `package.json`).

## Чеклист

- [ ] **Спайк библиотеки (Фаза 0.5)** — `checkSupport()` → `create()` → `checkDeviceEligibility()` →
  `ensureModelReady()` с прогрессом → `sendMessage` → получить токены. Заводить ADR под
  `docs/plans/llama2/adr/` на каждое расхождение с ожиданиями библиотеки (см. план §1, §10 — Capacitor-
  адаптеры `local-ai` ни разу не запускались на реальном устройстве авторами библиотеки).
- [ ] **Android 7/8 smoke (Фаза 0.6)** — тот же спайк на слабом устройстве: eligibility корректно
  деградирует (`verdict: 'no'`/`checkSupport` false) вместо краша приложения.
- [ ] Открыть вкладку «AI» в сайдбаре — видна только на native-сборке.
- [ ] На слабом устройстве, если eligibility `verdict: 'no'` — виден понятный блок «недоступно»,
  без кнопки «всё равно скачать» (политика `block` по умолчанию).
- [ ] Скачать модель — прогресс-бар обновляется, не зависает.
- [ ] Создать новый AI-чат → сразу открывается, без ожидания модели.
- [ ] Отправить сообщение → токены стримятся видимо (не одним куском в конце).
- [ ] Отменить генерацию (кнопка «стоп») → частичный ответ сохраняется, UI не виснет.
- [ ] Отправить второе сообщение в тот же чат → заметно быстрее первого (session-cache reuse, ТЗ §9.3
  — визуальное подтверждение, не только доверие юнит-тестам).
- [ ] Попытаться отправить сообщение во ВТОРОМ AI-чате, пока первый ещё генерирует → composer
  дизейблен, показан `ai.busyOtherChat`.
- [ ] Переключить аккаунт (если добавлено несколько) → история AI-чатов второго аккаунта не содержит
  чатов первого (per-account `databaseName`, план §4.2).
- [ ] Выйти из аккаунта во время активной генерации (roadmap 7.2) → logout не подвисает/не крашится
  (автоматическая регрессия уже покрыта юнит-тестом
  `ai-chat-store.test.ts` → «logout mid-generation…», но реальный `releaseRuntime()`/SQLite-закрытие
  на устройстве стоит перепроверить вручную — гонка с закрытием соединения воспроизведена только на
  фейковых портах).
- [ ] Settings → Local AI показывает то же число прогресса, что и открытый AI-чат одновременно (один
  стор, план §8 п.4) — открыть оба экрана параллельно (если платформа позволяет) или
  последовательно во время активной загрузки.
- [ ] «Проверить обновления» в Settings → Local AI не виснет и не дублирует прогресс-бар.
- [ ] Свернуть приложение во время активной генерации, вернуться — не крашится (`autoUnloadOnBackground:
  true`, roadmap 7.1 — подтвердить, что задержка возврата приемлема на слабом устройстве; если нет —
  пересмотреть решение, см. `decisions.md`).
- [ ] Android «назад» из открытого AI-чата — ведёт себя как в обычном чате (закрыть чат → назад в
  список), не сворачивает приложение.
- [ ] Если включён Tor `always` — модель всё равно скачивается (подтверждает
  `decisions.md`'s Фазу 7.3 finding), но пользователь видит предупреждение в Settings → Local AI.
- [ ] Открыть баг-репорт из контекста AI-чата/Settings → Local AI (или просто после того, как AI
  использовался в сессии) — отчёт содержит секцию `local-ai logs` (roadmap 7.6).
