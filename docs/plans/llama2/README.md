# AI-чаты (`local-ai`) — планы

Интеграция готовой библиотеки [`local-ai`](../../../../inetpub2026/localai) (офлайн-инференс LLM
через `llama-cpp-capacitor`, ~4B Q4_K_M мультиязычная модель) в Forta Chat как новая группа чатов
«AI» — отдельная вкладка в сайдбаре, свой список, сообщения и чаты хранятся локально в Dexie.
Библиотека пока доступна только локально (`C:\inetpub2026\localai`, не опубликована в npm).

**Ключевые находки этой сессии** (детали в `decisions.md`):
- Реальный замер APK: `local-ai` + 4 нативных плагина добавляют **+24 MB** (сжато) на `arm64-v8a`
  (debug-сборка) — почти целиком один файл, `libllama-cpp-arm64.so`.
- Скачивание модели **всегда идёт мимо Tor** (Android `DownloadManager`, подтверждено чтением
  исходников плагина, не только предположение) — плюс для скорости, минус для приватности при
  `torMode: 'always'`; в Settings добавлено предупреждение.
- Обнаружена и закрыта тестом реальная гонка: `releaseRuntime()` во время активной генерации мог
  выбрасывать `"database is not open"` наружу из `sendMessage()` — теперь трактуется как штатная
  отмена, не ошибка.
- Dexie `liveQuery()` не отдаёт ни одной эмиссии в этом тестовом окружении (happy-dom +
  fake-indexeddb) — не баг этого плана, существующее ограничение тестовой инфраструктуры проекта;
  тесты Mode B проверяют состояние через репозитории напрямую, не через реактивные `store.messages`.

## Ключевые решения

- **Dexie — источник истины, `local-ai` — только память модели (Mode B).** Список AI-чатов и
  сообщения, которые видит пользователь, живут в Dexie (`ChatDatabase.aiChats`/`aiMessages`, та же
  БД, что и Matrix-данные — logout/переключение аккаунта чистит их бесплатно). Внутренняя SQLite
  `local-ai` — невидимое пользователю зеркало для построения промпта/session-cache, синхронизируется
  идемпотентными `upsertChat`/`appendMessages`.
- **Не Matrix.** AI-чаты не проходят через `SyncEngine`/`EventWriter`/шифрование — это чисто
  локальная, нессинхронизируемая между устройствами история (соответствует ограничению самой
  библиотеки: без облачной синхронизации в v1).
- **Эмбеддингов нет в этой фазе.** Манифест обязан содержать embedding-артефакт (схема требует), но
  приложение никогда не вызывает `ensureEmbeddingReady()`/`vectors.*` — RAG отложен в заблокированную
  Фазу R.
- **Модель — 4B Q4_K_M**, скачивается по требованию: либо из Settings → Local AI, либо при первом
  обращении к AI-чату (не эагерно на старте приложения).
- **Прогресс загрузки/обновления — один Pinia-стор** (`entities/local-ai`), на который подписаны и
  Settings, и открытый AI-чат — согласованное состояние без дублирования опроса.
- **Только native (Android/iOS).** `llama-cpp-capacitor` не поддерживает web — на web/Electron вкладка
  «AI» скрыта через `isNative`, внутри дополнительно проверяется `checkSupport()`.
- **Логи `local-ai` включены и подключены к существующему бажрепорту.** Библиотека умеет опциональный
  персистентный лог-стор (`config.logging`, добавлено в библиотеку 2026-08-11) — включаем его и
  прикладываем `exportLogs()` к отчётам из `features/bug-report` вместо отдельной кнопки экспорта:
  единственный канал диагностики на реальных устройствах, где Capacitor-адаптеры `local-ai` не
  тестировались авторами библиотеки (см. план §11).
- **UI — отдельные компоненты, не расширение `ChatWindow.vue`.** AI-чат проще Matrix-чата (только
  текст, стриминг, без шифрования/медиа/реакций) — по прецеденту `entities/channel`/`features/channels`
  (своя вкладка, свой стор, свои компоненты, Matrix-конвейер не трогается).
- **Composer переиспользуется как есть** — не пишем новый текстовый инпут, чтобы не пересекаться с
  параллельной задачей по клавиатуре.
- **`local-ai` устанавливается как `file:` зависимость** до публикации в npm; после публикации —
  замена версии без изменения кода потребителя (subpath-экспорты не меняются).
- **Мультиаккаунт:** SQLite-БД `local-ai` — per-account (`databaseName`), файл модели — общий для всех
  аккаунтов на устройстве (контент-адресован, повторное скачивание не нужно).
- **Android 7 (minSdk 24) совместимость библиотеки не подтверждена измерением** — обязательный ручной
  спайк на реальном/эмулированном слабом устройстве в Фазе 0, полагаемся на встроенные
  `checkSupport()`/`checkDeviceEligibility()` для корректной деградации, не обходим их.
