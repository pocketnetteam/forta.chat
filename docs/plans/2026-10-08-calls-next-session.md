4. **Находки по Tor** — разобраны 2026-10-08 на отладочной сборке `f5c60d41` (Samsung, CDP, `adb forward tcp:18181
   tcp:8181` к прокси). Tor на телефоне возвращён в «Никогда». Нужно решение владельца:
   - **Отчёт о баге не уходит под Tor — причина найдена, она шире отчётов.** Обратный прокси `libreverseproxy.so`
     (Go, исходник у разработчика pocketnet) пересылает целевому серверу входящий `Host` без порта, то есть
     `Host: 127.0.0.1`, а не хост из URL (httpbin через прокси: `"Host": "127.0.0.1"`; с `-H "Host: httpbin.org"` —
     `httpbin.org`). Серверы с виртуальными хостами отвечают ошибкой: `api.github.com` 400 (страница «Bad request ·
     GitHub» — отсюда «Не удалось отправить»), `bastyon.com` 404, `forta.chat` 421, Википедия 400; с правильным `Host`
     все 200. Работают только серверы, которым `Host` безразличен: `matrix.pocketnet.app`, `1.pocketnet.app:8899`,
     `explorer.pocketnet.app`. Из JS не обойти: `Host` — запрещённый заголовок для `fetch`. Варианты: (а) новая сборка
     прокси от pocketnet — одна строка, исходящий `Host` = хост цели с нестандартным портом (заодно 120-секундный
     таймаут); (б) свой прокси на 8181 в Kotlin (OkHttp через SOCKS 9051) вместо бинарника; (в) на будущее —
     `ProxyController` WebView + `HTTPTunnelPort` Tor (TLS до сервера, без перезаписи URL).
   - **164 с вместо 37 с — не воспроизвелось.** Звонок под Tor «Всегда»: история 30 с при 33 с на вебе; звонок, во время
     которого Tor включили и он поднялся (59 с загрузки): история 100 с при 103 с. Длительность считается тиками от
     Connected до Ended и не может обогнать стену — в #1441 JS считал звонок живым 164 с. Догадка: пуш об отбое не
     пришёл, а /sync через Tor висел до 120-секундного таймаута прокси (37 + ~127 с). Наблюдать.
   - **Tor из настроек без перезапуска идёт напрямую — не воспроизвелось.** После «Подключён» (59–75 с) запросы
     страницы и звонок шли через Tor, счётчик «напрямую» не рос (474,5 KB до и после). Код каждого запроса
     спрашивает натив заново. Исходное наблюдение, скорее всего, — долгая первая загрузка Tor на слабом Wi-Fi: до
     готовности «Всегда» по правилу `ca30651c` идёт напрямую.
   - **Решение владельца по правилу «Всегда напрямую до готовности Tor»** (`TorRouteDecider.kt:26`, с июля) — в силе.
