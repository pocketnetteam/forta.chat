### Task 4: Tor JS-stubs (no Tor on iOS)

**Files:**
- Modify: `src/shared/lib/tor/tor-service.ts`

**Step 1: Branch the public methods on `isIOS`**

Per the project decision, iOS does not ship Tor. The TS API surface stays identical to keep callers happy; the methods become no-ops returning the "ready, mode never" shape:

```typescript
import { isIOS } from '@/shared/lib/platform';

class TorService {
  ...
  async init(mode: 'always' | 'auto' | 'never' = 'always'): Promise<void> {
    if (isIOS) {
      this._ready.value = true;
      this._state.value = 'NEVER';
      this._proxyPort.value = 0;
      return;
    }
    if (!isNative) {
      this._ready.value = true;
      return;
    }
    // ...existing Android/Capacitor body
  }

  async stop(): Promise<void> {
    if (isIOS) return;
    // ...existing
  }

  async configure(...) {
    if (isIOS) return;
    // ...existing
  }

  async verifyTor(): Promise<{ isTor: boolean; ip: string; error?: string }> {
    if (isIOS) return { isTor: false, ip: '', error: 'tor_disabled_on_ios' };
    // ...existing
  }
}
```

**Step 2: `matrixBaseUrl` getter**

Already returns `''` when not native or not ready, which means callers fall back to direct connection. iOS path lands here naturally — no extra branch required.

**Step 3: Tor settings UI**

Audit `src/widgets/sidebar/ui/SettingsContentPanel.vue` (and any Tor toggle). Hide the Tor section on iOS:

```vue
<TorSection v-if="!isIOS" />
```

This avoids a confusing toggle that does nothing.

**Step 4: Update tests**

Add an iOS branch in `src/shared/lib/tor/tor-service.test.ts` confirming `init()` is a no-op and `verifyTor()` reports `tor_disabled_on_ios`.

**Step 5: Commit**


### Task 5: Locale stub (no `LocalePlugin` on iOS)

**Files:**
- Audit: any caller of `LocalePlugin` (search `'Locale'` in `registerPlugin`).

**Step 1: Skip native call on iOS**

Wherever JS calls `LocalePlugin.setLocale(...)` or similar, gate it:

```typescript
if (!isIOS) {
  await LocalePlugin.setLocale({ locale });
}
```

iOS apps inherit locale from `Bundle.main.preferredLocalizations`, which auto-resolves from the system Settings → General → Language & Region. Manual locale override at runtime is rare and out of v1.

**Step 2: Document in README**

Add a one-liner in `README.md` and `README.ru.md` "Known iOS differences" section: "iOS uses the system locale; in-app language switch will take effect after a relaunch on iOS."

(If post-launch in-app switching is required by product, write a small Swift plugin that updates `UserDefaults["AppleLanguages"]` and triggers a UI rebuild — but defer until product asks.)

**Step 3: Commit**

```
git add src/entities/locale/model/stores.ts src/shared/lib/i18n/... README.md README.ru.md
git commit -m "feat(ios): drop LocalePlugin call (use system locale)"
```

### Task 8: AppDownloadBanner — iOS App Store link

**Files:**
- Modify: `src/features/app-download-banner/ui/AppDownloadBanner.vue:12-15`

**Step 1: Detect iOS browser users and show App Store link**

Currently the banner is shown only for Android browsers (`isAndroidBrowser` = `isWeb && /Android/i.test(...)`). Mirror it for iOS Safari users browsing the web app:

```typescript
const isAndroidBrowser = isWeb && /Android/i.test(navigator.userAgent);
const isIOSBrowser    = isWeb && /iPhone|iPad|iPod/i.test(navigator.userAgent);
const visible = ref(false);

onMounted(() => {
  if ((isAndroidBrowser || isIOSBrowser) && !localStorage.getItem(DISMISS_KEY)) {
    visible.value = true;
  }
});

const downloadUrl = computed(() =>
  isIOSBrowser
    ? 'https://apps.apple.com/app/idXXXXXXXX'
    : 'https://github.com/pocketnetteam/forta.chat/releases/latest'
);
```

(Replace `idXXXXXXXX` with the real App Store ID once available — leave a TODO + a fallback to the website until then.)

**Step 2: Commit**

```
git add src/features/app-download-banner/ui/AppDownloadBanner.vue
git commit -m "feat(banner): show App Store link to iOS Safari users"
```
